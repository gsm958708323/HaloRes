# 资源生命周期与内容版本激活

状态：已采纳，2026-10-31。

所提供的设计方案选择自研 AssetBundle 内核。项目使用 Unity 6000.0.32f1，
并固定使用 UniTask 2.5.11 处理 Unity 异步操作和对外异步 API。
共享完成源采用标准 `TaskCompletionSource`，因为它支持任意数量的独立等待者。
调用方的取消请求不会传递到 Provider。

资源持有关系从 `AssetScope` 传递到内部的 `AssetManager`，
再通过 `IAssetProvider` 传递到内部的 `BundleManager`。
每次借用对应一个可幂等归还的租约。每个存活的资源句柄，在 Provider 加载成功后，
都必须对应一次卸载。每次成功的 Provider 加载，持有主包及其扁平依赖闭包中每个包的一份引用。
包之间不互相持有引用，因此循环依赖不会形成无法归零的引用环。

只有管理器可以修改计数。运行时 Manifest 将通过校验的 JSON 映射为不可变对象和只读集合。
重复地址、不安全路径、重复依赖索引、无效索引及不完整的依赖闭包，均在数据边界处拒绝。
资源表以地址为键；类型不兼容的请求会失败，子资源不在约定的 MVP 范围内。

`LateUpdate` 依次处理实例销毁完成后的归还、资源卸载和资源包卸载。
Unity 的 `Destroy` 会延迟执行，因此实例租约会一直保留到 Unity 原生实例与 `null` 比较相等时，
以覆盖调用 `Destroy` 到实际销毁之间的时间窗口。同帧内，在开始卸载之前再次借用，
会复用原句柄。一旦开始卸载，句柄立即从地址表移除；后续请求会获得新的句柄。

`Instantiate` 可能在返回克隆实例之前执行用户编写的 `Awake` 方法。
创建实例期间，如果发生重入归还，租约会暂缓处理。实例创建返回后，作用域再次检查取消与释放状态，
对于无法交付的实例，先销毁实例，再归还其对应的资源引用。

场景只支持叠加加载。场景卸载完成后，才归还对应的包引用。
如果 Unity 拒绝卸载，句柄保留为可观测的 `UnloadFailed` 状态，驱动器会在后续帧重试。
启动场景必须始终保持加载。调用方可以等待 `ShutdownAsync`，确认系统已彻底清理；
`Dispose` 只发起清理，存在未完成的异步操作时仍需持续驱动系统。

内容更新在运行时初始化之前执行。资源包和 Manifest 均以 SHA-256 内容哈希命名。
所有变更文件先下载到临时文件，校验长度和哈希后，再移入内容仓库。
只有完整版本的全部文件就绪后，才原子替换当前版本文件。
文件锁用于防止多个更新过程同时激活同一个内容仓库。
已发布版本不可变，系统拒绝版本降级。旧内容保留在磁盘上，确保更新失败时仍可使用上一版本。
当前不引入运行时目录变更、断点续传、按需下载、加密或 LRU。

SHA-256 用于检查完整性，不能证明发布者身份。生产环境的远程服务必须使用 HTTPS 和可信的部署渠道。
设备相关的文件系统与内存行为，仍需在 Android/iOS 真机上验证。

本次未主动引入技术债务或兼容路径。后续功能应以实测需求为起点，并通过新的架构决策记录说明。
